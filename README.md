# Экспертная система анализа конфиденциальности (ЛР № 2)

**Репозиторий:** https://github.com/glebtyryshkin/inf-sec

Учебный проект по дисциплине «Информационная безопасность»: экспертная система на Python,
которая **логически выводит** наличие нарушения режима конфиденциальности по тексту
(введённому с клавиатуры или прочитанному из файла), а не ищет ключевые слова.

Система определяет, **какой федеральный закон нарушен, какая статья и почему**, выбирает
действие (удалить / маскировать / ничего не делать), а при нехватке данных выдаёт
«Требуется ручная проверка» со списком уточняющих вопросов. Все инциденты пишутся в
журнал `security_log.txt` с частично замаскированным исходным текстом.

## Быстрый старт

```bash
# ввод с клавиатуры (завершение — строка /end)
python main.py

# анализ одной строки или файла
python main.py --text "Сотрудник ФНС передал данные о налоговых платежах компании её конкуренту."
python main.py --file samples/case_08_fns_konkurent.txt

# демонстрация 10 сложных примеров из задания
python main.py --demo

# прогон набора тестовых текстов
python main.py --batch tests/cases.json

# машиночитаемый вывод
python main.py --file samples/case_07_bank_notarius.txt --json

# модульные тесты (44 теста)
python -m unittest discover -s tests -t .
```

Коды возврата: `0` — нарушений нет, `1` — ошибка ввода (файл не найден, пустой текст),
`2` — выявлено нарушение, `3` — требуется ручная проверка.

## Архитектура вывода

```
текст ──► извлечение сущностей ──► рабочая память ──► прямой вывод (forward chaining)
             (онтология,                 факты               правила → новые факты
              падежные эвристики)     предикат(значение)      до неподвижной точки
                                                                    │
                          объяснение ◄──────────────────────────────┤
                       (закон, статья,                              │
                        цепочка условий)                            ▼
                                              агрегация: вердикт, действия,
                                              конфликты, ручная проверка, журнал
```

1. **Извлечение сущностей.** Онтология содержит стемы-маркеры, поэтому распознаются
   словоформы («передал / передача / передаче»). Падежные эвристики отличают
   действующее лицо («Сотрудник ФНС передал…») от получателя («…конкуренту»,
   «…в полицию») и от субъекта данных («данные **о** пациенте»). Распознаются
   отрицания («не передавал») и противоречия («без согласия» + «согласие подписано»).
2. **Рабочая память.** Факты вида `object=налоговая_тайна`, `recipient_role=конкурент`,
   `consent=нет`; каждому факту соответствует коэффициент уверенности (прямой маркер —
   1.0, косвенный — 0.6).
3. **Прямой вывод.** Правила применяются до неподвижной точки: сработавшее правило
   добавляет факты, которые включают следующие правила. Например:
   `нотариус + наследство + запрос` → `документ = нотариальный запрос` →
   `передача банковской тайны нотариусу законна (ч. 9 ст. 26 395-1-ФЗ)`.
4. **Объяснение.** Для каждого вывода сохраняется цепочка: какие факты и какие фрагменты
   текста его включили, какой закон и какая статья нарушены, что делать.
5. **Неполнота данных.** Если правило почти применимо, но не хватает обстоятельства
   (например, неизвестно наличие согласия), формируется запись «Требуется ручная проверка»
   с уточняющими вопросами. Гипотезы с уверенностью ниже порога (0.7) не превращаются
   в обвинение, а попадают в раздел «Возможные нарушения — требуют проверки».
6. **Агрегация.** Если нарушено несколько законов одновременно, выводятся все составы,
   а действие выбирается по наиболее строгому режиму; при конфликте «нарушение ↔ законное
   исключение» система сообщает о спорной ситуации.

## База правил (фрагмент)

| № | Условие | Вывод | Норма | Действие |
|---|---|---|---|---|
| R-01 | налоговая тайна ∧ получатель = конкурент ∧ согласия нет | нарушение | ст. 102 НК РФ (146-ФЗ), ч. 2 ст. 183 УК РФ | удалить |
| R-02 | налоговая тайна ∧ получатель = налоговый орган ∧ цель = проверка | законно | п. 1 ст. 102 НК РФ | ничего не делать |
| R-03 | налоговая тайна ∧ источник = налоговый орган ∧ получатель = конкурент/третье лицо | нарушение | подп. 8 п. 1 ст. 32, ст. 102 НК РФ; ч. 2 ст. 183, ст. 285, 290 УК РФ | удалить |
| R-05 | коммерческая тайна ∧ разглашение без согласия и NDA | нарушение | п. 9 ст. 3, ст. 10, 11, 14 98-ФЗ; ст. 1472 ГК РФ | удалить |
| R-07 | Due Diligence ∧ сделка не состоялась ∧ использование сведений | нарушение | ст. 1472 ГК РФ; 98-ФЗ; ст. 14.7 135-ФЗ | удалить |
| R-08 | банковская тайна ∧ нотариус ∧ нотариальный запрос | законно | ч. 9 ст. 26 395-1-ФЗ; ст. 1171 ГК РФ | ничего не делать |
| R-09 | банковская тайна ∧ нотариус ∧ отказ ∧ наследство | нарушение | ч. 9 ст. 26 395-1-ФЗ; ст. 1171 ГК РФ | ничего не делать (устранить нарушение) |
| R-12 | врачебная тайна ∧ полиция/суд ∧ письменный запрос | законно | п. 3 ч. 4 ст. 13 323-ФЗ | ничего не делать |
| R-13 | врачебная тайна ∧ полиция/суд ∧ нет письменного запроса | нарушение | ч. 2 ст. 13 323-ФЗ; ст. 13.14 КоАП РФ; ст. 137 УК РФ | удалить |
| R-14 | врачебная тайна ∧ третье лицо ∧ нет согласия | нарушение | ч. 2 ст. 13 323-ФЗ | удалить |
| R-15 | ПДн ∧ передача ∧ нет согласия и законного основания | нарушение | ст. 6, 7, 9 152-ФЗ; ст. 13.11 КоАП РФ | удалить |
| R-16 | ПДн ∧ цель = рассылка ∧ нет согласия | нарушение | 152-ФЗ; 38-ФЗ «О рекламе» | удалить |
| R-18 | признаки сведений военного характера | ручная проверка | Закон РФ № 5485-1; ст. 275, 283 УК РФ | удалить |

Полный перечень (26 правил, включая правила выведения промежуточных фактов и законные
исключения) — в файле `privacy_expert/rules.py`, функция `build_rule_base()`.

## Журнал инцидентов

```
2026-10-13 02:31:07 | НАРУШЕНИЕ | ФЗ № 146-ФЗ … — ст. 102 НК РФ; ст. 183 УК РФ |
объект=налоговая тайна; получатель=конкурент | действие=удалить | источник=cli |
правила=R-01 | уверенность=1.00 | текст: «Сотрудник Ф*** перед*** данные о нал*** …»
```

Прямые идентификаторы (ФИО, счета, карты, телефоны, e-mail, ИНН, суммы) маскируются
частично: журнал не должен сам становиться носителем тайны.

## Обработка исключений

| Ситуация | Поведение |
|---|---|
| Файл не найден / это каталог | `InputFileNotFound`, код возврата 1, понятное сообщение и подсказка |
| Пустой текст (или только пробелы) | `EmptyInputError`, код возврата 1 |
| Неизвестная кодировка | `EncodingError` (перебор UTF-8, UTF-8-BOM, CP1251) |
| Несколько законов одновременно | выводятся все составы + предупреждение, приоритет по риску |
| Противоречивые данные | «Требуется ручная проверка», конфликт правил фиксируется |
| Некорректная база правил | `RuleBaseError` при инициализации системы |

## Что не публикуется

Текст отчёта по лабораторной работе и скриншоты (`docs/`) остаются локально и в репозиторий не добавляются: в отчёте есть персональные данные (ФИО, группа, подписи). Скрипты `tools/build_report.py` и `tools/make_screenshots.sh` позволяют собрать отчёт и скриншоты из исходного документа и реального вывода программы.

## Ограничения

Система — учебная экспертная система, а не юридическая консультация: вывод строится
только на сведениях, извлечённых из текста, и на заложенной базе правил. Во всех спорных
случаях система прямо требует ручной проверки юристом или службой информационной
безопасности.
